# Pocketpistol: notes for agents

Self-hosted bulk mail that runs entirely inside PocketBase's JS hooks (goja, not Node), with PocketPages for the public pages. See README.md for layout and how to run it.

## Agent-first

Every feature must be usable by an agent through `/mcp`, not only by a person in the UI. A feature isn't done until it has an MCP tool.

- **Logic lives in `pb_hooks/lib/`** as plain functions that take arguments and return plain JSON-able objects.
- **Everything else is a thin layer over `lib/`:** MCP tools (`lib/tools.js`), the admin extension (`admin/`) and the public pages (`pages/`). None of them should contain business rules that the others would need to repeat.
- **When you add or change a feature**, add or update its tool in `lib/tools.js` in the same change. The tool description is the agent's only documentation: say what the tool does, what it won't do and any side effects (for example, "nothing is sent").
- The current tools still hold their logic inline. Move it into a `lib/` module as soon as a second caller (admin UI or a page) needs it.

## MCP endpoint

- `POST /mcp` in `pb_hooks/pocketpistol.pb.js`: MCP Streamable HTTP, stateless JSON, no SSE. `GET /mcp` returns 405.
- The protocol layer and the generic `pb_*` admin tools come from [pbjsmcp](https://github.com/benallfree/pbjsmcp) (`require('pbjsmcp')`). Don't copy `mcp.js` into this repo; fix it upstream.
- Auth is `$apis.requireSuperuserAuth()`. Any superuser token works, including long-lived ones from `POST /api/collections/_superusers/impersonate/{id}`. Scoped API tokens (and OAuth for chat-app connectors later) are planned; design tools so they could later be gated by scope.
- Destructive tools must set MCP's `destructiveHint` annotation.

## PocketBase hooks rules

- Handlers run in isolated goja runtimes. Anything a handler uses must be `require`d **inside** the handler, as `require(\`${__hooks}/lib/x.js\`)`. Top-level variables from the `.pb.js` file are not visible in handlers.
- Never put server code in `pb_hooks/admin/`. Every file there is served publicly at `/_/extensions/pocketpistol/`.
- Schema lives in `lib/schema.js` and is imported on every boot with `$app.importCollections(collections, false)`. Collection and field ids are fixed (`pp_*`) so re-imports update in place. Never change an existing id; add new fields with new ids. There are no migration files.
- All collections are superuser-only (`null` rules). Public pages reach data through hooks, not the REST API.
- Type definitions are in `pb_data/types.d.ts` (generated by PocketBase, gitignored).

## Contact sync

Other apps mirror their users into `subscribers` through `lib/contacts.js` (HTTP: `PUT|DELETE /api/pocketpistol/contacts/{source}/{external_id}`, `POST /api/pocketpistol/contacts/batch`; MCP: `upsert_contacts`, `delete_contact`, `list_tags`). The source owns `tags`, `attributes`, `source_suppressed` and `source_updated` and always sends the full tag set. Pocketpistol owns `status` and `local_tags`; sync must never change them.
